# S7 — Move to the SDK the phone's Expo Go speaks

**Asked for:** "I want the app to open on my phone again, now that Expo Go on it
has moved to SDK 57."

**What came back:** SDK 54 → 57 one step at a time (55, 56, 57), gate green at
each; `expo` re-pinned `~57.0.26`. [ADR-0013](../adr/0013-expo-sdk-follows-the-store-expo-go.md)
supersedes 0007: principle kept (the SDK is whatever Expo Go on the phone speaks),
premise replaced — "the store is capped at 54" was false; 55 and 56 were simply
never published to the Play Store, then the client jumped three SDKs at once. No
app source changed; same 31 tests; one config line written by the tooling.

**What QA caught:** no defect. It ruled the edits outside `app/` in scope via AC5,
and turned the one real unknown into demo step 5: since SDK 56 Expo's own `fetch`
replaces React Native's, and [ADR-0009](../adr/0009-geocoding-via-nominatim.md)
depends on our `User-Agent` surviving it. Settled on the phone indirectly only
(Nominatim answered). Found afterwards by me: the tunnel failed with
`ERR_NGROK_4018` on `develop` too, so not S7, cured by a WSL restart; and DevTools
opened from the phone lands on "127.0.0.1 refused to connect".

**What I'd specify differently:** QA's direct check for the story's one real risk
depended on DevTools, which has never worked in this environment
([ADR-0006](../adr/0006-test-and-lint-toolchain.md)). A demo step nobody can run
is a step that gets skipped. Next time: when an AC's risk has only one direct
check, ask whether that check actually works here *before* the demo, not during it.

**Method change:** none edited yet; the largest finding is a gap, recorded as the
first item of the next session (backlog `## Spotted`, "Method gap"). All **core**.
- **Work that is not a story has no home.** The advisory re-triage was correctly
  out of S7's scope and had no other container, so the PO, the architect and the
  dispatching session all deferred it to me — the session first, in its own brief
  to the PO. The Spotted header ("Triage these yourself") is the only text that
  assigns triage, and it assigns it to the supervisor. Rule to build on: every
  operation is motivated by a tracked work item; a needed task that fits no scope
  means the scopes are wrong.
- **Merge strategy is a kickoff decision, not a universal rule.** PR #4 was
  squash-merged though ADR-0013 describes one commit per SDK step, and no ADR
  decided merge style (rule 8: an open question). For this project I chose merge
  commits; the method should make the architect guide each new project to its own.
- **`pipefail` slip.** The architect ran an install through `| tail` without
  `pipefail` and saw a false `EXIT 0`, caught from the error text. Logged here so it
  counts toward [ADR-0011](../adr/0011-one-gate-command-and-pipefail.md)'s "third
  occurrence in a log" signal.
